# CI flake 诊断

只在任务是调查一个已有的概率性测试或 CI 失败时使用本工作流。保持请求的读写范围：诊断不授权修复、重跑 workflow 或改动 CI 配置。

## 冻结证据

记录仓库、workflow、job、提交 SHA、runner 标签、时间戳、确切的失败测试或命令，以及第一个稳定的失败签名。把基础设施消息与测试输出分开。

比较多次失败与通过运行。优先同 SHA 的运行；做不到时，验证被比较的提交之间相关测试与 CI 配置完全一致。一次通过的重跑不证明基础设施故障，一次超时也不证明产品竞态。

用 Actions 日志与元数据判断失败是否重叠在同一个宿主或资源命名空间上。保留支持性运行的链接，而不是粘贴大段日志。

## 分类失败

从记录的证据分类，而不是从最终的修复分类：

- **宿主资源碰撞**：同一个端口、socket、数据库、可预测路径、缓存或外部命名空间被独立进程或 job 占用。
- **生命周期不完整**：teardown 在子进程、worker、流、服务器或回调达到静默之前返回；后续输出或改动出现在另一个测试里。
- **进程全局污染**：结果取决于测试顺序，或泄漏的 `process.env`、`cwd`、假时钟、全局对象、mock、locale、模块状态。
- **负载敏感同步**：用 sleep、轮询间隔或假设的事件循环轮次替代可观察的就绪或完成信号。
- **平台或入口路径不匹配**：失败稳定跟随某个操作系统、shell、文件系统规则、源码/构建模式或可执行入口。时间戳精度、环境变量名大小写、句柄释放时机与权限语义在 Windows 与 POSIX 之间都不同，所以在 macOS 上通过的用例对 Windows lane 什么也证明不了。
- **产品并发缺陷**：测试控制着自己的资源，用显式重叠确定性地复现，并暴露已交付行为里的竞态。
- **外部 provider 瞬态**：失败由活的 API 或网络边界拥有，并符合其记录的退避策略。
- **runner 基础设施**：checkout、依赖下载、磁盘、宿主进程或 runner 服务独立于测试命令失败。分配这一类之前要求直接的 runner 证据。自建池拿不到宿主指标时，说明这一点，并从日志确实携带的信息分类：同一池上无关分支重复出现的同一签名，即使无法检查宿主，也是共享宿主竞争的证据。

如果证据支持多个独立事实，逐个报告。不要把超时、信号、退出码与断言塌缩成一个推断出的结论。

## 复现最小相关拓扑

从拥有的测试文件或聚焦的测试名开始。只把并发提高到第一个能复现签名的拓扑：

1. 单个测试进程；
2. 并发测试或文件；
3. 多个独立的 Vitest 进程；
4. 拥有该行为的仓库门禁及其配置的 worker 数；
5. 共享被牵连宿主资源的独立 job 或 runner 进程。

匹配实际的 Vitest 配置、环境开关、源码/构建模式与平台。不要为了制造不同的失败而调低生产超时或加随机负载。

签名属于当前宿主跑不了的平台时，阶梯停在最后一个可达的台阶。记录这个限制，而不是用另一个平台上的通过运行替代；然后把 CI 当作复现环境，每次只改一个可疑的拥有者，保持结果可归因。

怀疑竞态时，用出现在争用转移点的 barrier 替换概率性时序。怀疑宿主碰撞时，要么证明同一标识符被同时获取，要么证明原子唯一分配消除了冲突。

## 在拥有者处修复

授权实现时，修那个分配资源、发布就绪、改全局状态或拥有 teardown 的组件。不要把失败藏进快照规范化器、重试包装、更宽的超时、全局串行设置或更弱的断言。

保持稳定 fixture 数据与活的资源分配分离。录制的 URL 可以保持稳定，而 fixture 把它的传输映射到操作系统分配的端口；稳定的期望路径可以继续作断言，而不会变成共享的可写目录。

## 收束调查

证据完整当且仅当：

- 原始签名有一个有依据的分类；
- 最小相关拓扑能复现它，或外部证据充分且复现限制是明确的；
- 授权的修复在负控制或修复前状态下失败，之后在同一拓扑下通过；
- 资源拥有者要求的任何并发进程、恢复或静默 teardown 证明都通过；
- 剩余的 Actions 检查按观察到的状态报告为通过、待跑、跳过或失败。

不要跑到某个测试碰巧通过就把那个结果称为稳定。选定的证据确立结论后就停止，或报告阻塞分类的缺失事实。
