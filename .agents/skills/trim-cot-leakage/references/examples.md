# 泄漏样例

用它们识别统辖原则，不要当作文本模板。本文件故意引用泄漏措辞作为校准材料——[检索探针](recall-batteries.md)排除本 skill 的目录，这里的措辞不构成别处的许可。

## 死引用

### 有已提交拥有者的决策序号

**泄漏：**「斜杠输入按可见目录解析（决策 21）。」

**修复：**「斜杠输入按可见目录解析——这是纯文本引用决策，见 `docs/plans/completed/` 下拥有它的实施记录。」

序号在 HEAD 上解析不到任何东西；决策的名字与拥有它的文档路径可以。每个文件至少完整给出一次拥有者的路径（表面支持链接时用链接），之后的提及可以只用可搜索的名字。

### 没有拥有者的决策序号

**泄漏：**「注册表拒绝重名（决策 7：名字是扁平的，没有命名空间）。」

**修复：**「注册表拒绝重名；名字是扁平的，没有命名空间。」

没有任何已提交产物拥有「决策 7」，所以引用被删除——但它的事实从句（扁平名字）被重述为独立成立的表述，而不是随引用一起删掉。

### 审计项代码

**泄漏：**「渲染是纯函数：同一个快照，同一个字符串（审计 R3）。」

**修复：**「渲染是纯函数：同一个快照，同一个字符串。」

仓库里没有审计文档；那个代码是会话语境的简写，不携带任何命题。

### 未提交草稿的章节号

**泄漏：**「分层遵循设计（v2 §3.2）：`src/host/` 是纯宿主侧。」

**修复：**「分层：`src/host/` 是纯宿主侧。」

没人提交的草稿的 `§N` 无法解析。对照：「转义按 RFC 9110 §10.1.5」保留——外部标准按设计在仓库外解析，拥有自己 § 编号的已提交文档也可以按节引用。

### 计划阶段标签

**泄漏：**「`src/client/` 是外壳（T4）；P-I 迁移拥有适配器。」

**修复：**「`src/client/` 是外壳；适配器住在 `src/client/` 下对应的模块里。」

阶段标签索引的是一份从未落地的计划。用该阶段产出的东西替换标签。

## 栈与 PR 视角

### 持久散文里的栈位置

**泄漏：**「未来的远程后端会实现这个接口（沙箱后端是本栈的后一个 PR）。」

**修复：**「远程后端可以在不改渲染层的前提下实现这个接口。」

持久散文看不到栈。保留扩展点的契约；待办工作的家在 PR 本身、一个 `TODO`，或一个 issue。

### README 里的「本 PR」

**泄漏：**「本 PR 为快照列表增加按会话过滤。」

**修复：**「快照列表按会话过滤。」

README 活得比每个 PR 都长；把机制陈述为当前事实。

## 变更叙述与版本戳

### 带 PR 号的战争故事

**泄漏：**「颜色以前来自 `--widget-*` 令牌，而没有任何地方定义它们，所以一直渲染回退值；别名令牌修好了这个问题（PR #88）。」

**修复：**「颜色来自别名令牌；未定义的令牌渲染回退值。」

两个活事实都存活——当前机制与持续存在的失败行为——并重述为现在时。这个 bug 的传记属于 PR 与它的实施记录。

### 移除叙述

**泄漏：**「`probe` 字段随移除版一起消失了；现在徽章走通用投影对。」

**修复：**「徽章走通用投影对。」

从没见过 `probe` 的读者从它的缺席里学不到任何东西。「现在」与已删除的过去对比是版本戳。

### 已修复的回归 → 反事实现在时

**泄漏：**「这以前会对多字节标签双重编码。」

**修复：**「没有字节长度守卫时，多字节标签会双重编码。」

回归钉作为现在时反事实存活，并点名那个守卫；「以前」把它钉在仓库考古上。

### 索引性版本戳

**泄漏：**「本版批量渲染是同步的；异步路径是路线图工作。」

**修复：**「批量渲染是同步的。」（延后事项留在调用点的 `TODO(widget-batch):`。）

「本版」「v1」「今天」在合并的那一刻就过期了。计划记录变更故事小节里的历史阶段名（「首版交付了 X」）对当前状态安全；索引性的形式从来都不安全。

## 审阅编排

### 评审裁决作为散文

**泄漏：**「评审中被拒：缓存解析后的 spec。我们保持每次调用解析。」

**修复（放在实施记录的「备选方案」里）：**「**缓存解析后的 spec。** 被拒：spec 取决于每次调用的 cwd，按请求做键的缓存会提供过期的根。」

「备选方案」体裁是受认可的归宿；审查者与轮次不属于理由。

### 草稿序号

**泄漏：**「截至本笔记第 5 稿，加载器也会校验 manifest。」

**修复：**「加载器校验 manifest。」

已完成的记录陈述已交付的现实；它自己的修订历史住在 git 里。

## 对审查者说理的辩护

### 为断言辩护

**泄漏：**「这个断言是安全的——SDK 构造了这个对象，它只是没有把可选字段声明得足够严格。」

**修复：**「SDK 构造这个对象时填充了每个可选字段；声明的类型比运行时的保证更宽松。」

陈述维护者不得破坏的不变量。「它只是……」是在回答一个 HEAD 上没有人提出的反对。不变量在代码里可见时，改为删掉注释。

### 诉诸审查权威

**泄漏：**「这里正确，因为审查者确认了包装顺序。」

**修复：**（删除；包装顺序已在函数的 `@returns` 里陈述。）

正确性主张引用不变量或测试，从不引用人。

## 复述与推导

### 控制流叙述

**泄漏：**「我们先规范化标签，然后截断它，然后包装它。」

**修复：**（删除。）

注释下面三行代码已经把同一件事说清楚了。

### 测试走查

**泄漏：**「这个测试创建会话、发送两条消息、等待第二条回复，然后断言日志里有四条记录。」

**修复：**「两次往返必须恰好产生四条日志记录——投影会去重共享前缀。」

只保留非显而易见的断言理由；走查复述的是测试体。

## 含糊与规划残留

### 无标记的延后

**泄漏：**「暂时期望渲染大概没问题。」

**修复：**（删除；延后事项已经有它的 `TODO(name):` 标记。）

没有拥有者的含糊就是规划残留。标记不存在时就写一个（`TODO(name): 按动画帧合并`），而不是保留含糊。

### 含糊的量级

**泄漏：**「64 KiB 缓冲区对大多数情况应该够了。」

**修复：**「64 KiB 容纳观测到的最大帧（48 KiB）并留有余量；更大的帧在 `decode` 里响亮失败。」

用实际边界与超限时的失败行为替换含糊。

## 作者语言滑出

**泄漏：**「渲染器跑在 client 端；间距见 设计稿。---- 私有 ----」

**修复：**「渲染器跑在 client 侧；间距遵循 Figma 帧 `widget-badges`。」

工作语言片段与会话分隔符是转录残留。Figma 帧名保留：那是按设计在仓库外解析的外部出处。

### 双语围栏里的作者语言滑出

**两侧都泄漏：**逐字代码块里写着 `// 更新这里 before returning`。

**两侧都修复：**`// Update this before returning.`

改一次块，然后把那个逐字节相同的围栏复制进两个语言文件。在中文对应侧把代码注释翻译成不同措辞，即使两种注释各自都通顺，也破坏了配对契约。

## 行为可见的候选

**可疑：**一段导出的 JSDoc 写着「暂时可用」，而某个生成器把这句话复制进面向模型或用户的输出。

**错误：**纯散文清理时只重写源句子，或只手改生成产物。

**正确：**追踪源头的生成扇出，更新拥有者，重新生成所有派生物，并更新拥有它的验证场景。GUI 字符串要包含仓库要求的证据。若授权范围没有对应的验证场景，保持不变并报告延后。

## 保留项

### issue 引用在任何表面都持久

**保留：**「上限适用于完整的渲染值，含包装（issue #1470 拥有后续）。」

一次未经校准的清理删掉了它，理由是 issue 引用属于计划记录。方向错了：issue 从任何表面都能在 HEAD 上解析，「#N 拥有后续」是 README 里延后工作的受认可归宿。计划记录与实施记录额外认可的是引用*已合并的 PR* 作为证据。

### 死掉的名字引用不算「点名拥有者」

**删除：**「基于 widget 缝的徽章渲染器（见 widget 渲染 RFC）。」

一次未经校准的清理把它当作「按主题点名拥有文档」保留了下来。检验标准是可解析性，不是形式：没有任何已提交文件回应「widget 渲染 RFC」，所以这个指针是死的。存在已提交的拥有者就改指它；否则删除。

### 抑制理由

**保留（修正后）：**`// oxlint-disable-next-line no-non-null-assertion -- 单元素字面量保证下标 0 存在。`

理由从句是必需散文。陈述的理由为假时（原文写「上面的循环守卫证明帧存在」，而视野里没有循环），修正理由；绝不删除。

### 实测边界

**保留：**「深度上限（实测：512 层 ≈ 0.15s 同步；4096 会阻塞循环）。」

测量把常量钉住，防止无依据的重新调参；「实测」是区分数据与猜测的出处。

### 运行时新旧不是变更历史

**保留：**「旧连接排空后新连接才接受。」

这里的「旧」「新」命名的是交接中的两个活运行时对象，不是仓库状态。变更叙述禁令针对仓库历史，不针对生命周期词汇。

### 运行时自然时间不是版本戳

**保留：**「今天是几号？」

提示问的是运行时时钟；「今天」没有对比仓库状态。因为该文本到达模型，任何改写仍需拥有它的行为证据。

## 过度修正陷阱

下面每个陷阱都在清理中真实发生过并被审查拦下。精简任何段落前先枚举它的命题。

### 把义务翻成背书

**原文：**「这些直接注册是例外，待迁移到 slot。」

**过度修正：**「这些直接注册是受认可的例外。」

**正确：**「这些直接注册是例外，待迁移到 slot。」

「待迁移」是义务；「受认可」给现状背书。精简在缩短句子的同时反转了模态。

### 把假设提升为已交付功能

**原文：**「未来的基于 IPC 的 shell 会继承执行器并覆盖 `spawn`。」

**过度修正：**「基于 IPC 的 shell 继承执行器并覆盖 `spawn`。」

**正确：**「假设的基于 IPC 的 shell——当前不存在这样的 shell——会继承执行器并覆盖 `spawn`。」

只删未来标记，会把设计示意变成类已交付的断言。显式标注假设，而不是简单地去掉未来时。

### 删掉真事实连同周围的转录

**原文：**「门禁提示叙述检查顺序；提示文本同时也是 `verify-doc-typecheck` 编译所依据的内容。」

**过度修正：**「……」（整句作为叙述删除。）

**正确：**「提示文本是 `verify-doc-typecheck` 编译所依据的内容。」

半句是叙述，另一半是承重耦合。命题共享一行时，删从句而不是删整句。

### 保留数字却丢掉出处

**原文：**「4 MiB 上限是实测的：最大的生成 `py-types` 模块是 3.1 MiB。」

**过度修正：**「上限是 4 MiB；最大的生成 `py-types` 模块是 3.1 MiB。」

**正确：**保留「实测」。

没有「实测」，3.1 MiB 读起来像定义而不是观察，抬高上限前就没人会重新测量。
