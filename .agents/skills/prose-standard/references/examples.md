# 校准样例

用这些样例识别统辖原则，不要当作文本模板。「平衡」版本在保留每个承重命题的前提下，用该位置所需的最少解释。

## 保留每个事实从句

**原文：**「协调器按会话串行写入，在处置完成前冲刷缓冲事件，并把后端失败报告给调用方。」

**过度精简：**「协调器串行化持久化。」

**平衡：**保持原文。

删装饰与重复，不删命题。行为者、按会话的范围、处置顺序与失败可见性是各自独立的事实。

## 明确的技能范围是功能性的

**过度精简：**「读来源，用判断。」

**平衡：**「本 skill 是指导，不是完整清单。在具名检查之外仍需判断；书面要求仍然适用。」

**过度详细：**用几段辩护为什么清单不能替代独立推理。

保留明确的范围限制，因为它改变 agent 应用工作流的方式。删重复的劝说，不删护栏。

## 文档保留操作与验证

**过度精简：**「给这个工具加测试。」

**平衡：**「单测覆盖注册与清理，通过真实装配路径跑一遍，渲染输出变化时补冒烟。验证断言观察外部结果，而不是模型的报告。」

**过度详细：**走查每个 fixture 文件和示例代码里已经可见的断言。

保留测试层级、必需操作、真实入口路径与可观察验证。删除 fixture 叙述。

## 保留所有权与时序

**过度精简：**「处置期间会取消 provider 的工作。」

**平衡：**「运行期在释放子作用域之前请求 provider 取消；provider 负责在处置完成前 join 自己的 worker。」

**过度详细：**按时间顺序记述实现处置用的每个 promise 与回调。

行为者、顺序、所有权转移点与完成保证是各自独立的事实从句。

## JSDoc 保留边界时序

**过度精简：**「组合并缓存会话前缀。」

**平衡：**「在第一步与模型请求之前组合一次会话前缀。监听器的追加归入当前请求，且前置步骤的压力核算收到已组合的前缀。」

**过度详细：**走查实现该顺序的循环辅助函数、缓存字段与 promise 回调。

事件顺序及其对当前请求的后果是调用方可见行为，不是实现叙述。

## 为复杂代码定向而不叙述它

**过度精简：**「worker realm 支持。」

**平衡：**「拥有 worker realm 及其宿主桥。realm 初始化是单次的；处置会终止 worker 并拒绝后续调用。协议理由见 worker 隔离的实施记录。」

**过度详细：**逐段预览下面的类和辅助函数。

保留模块角色、依赖、职责与非显而易见的生命周期行为。链接架构理由，让代码自己展示局部控制流。

## 公共 JSDoc 要含失败

**过度精简：**「返回 realm 全局对象。」

**平衡：**「返回已初始化的 realm 全局对象。初始化尚未完成或 realm 已处置时抛出。」

**过度详细：**通向每个 throw 的内部状态机分支与确切辅助调用。

抛错与状态前置条件是调用方可见的契约事实。

## 保留简短的实现映射

**过度精简：**「由外部 API 支撑的搜索 provider。」

**平衡：**「把每个 provider 结果映射到共享的搜索结果字段：保留标题、URL 与文本，省略 provider 专有的排序元数据。」

**过度详细：**逐字段复述映射代码，包括名字相同、赋值显然的字段。

保留能解释适配器在哪里丢弃或改变信息的映射细节。

## 链接理由，同时保留本地契约

**过度精简：**「处置有文档，见生命周期记录。」

**平衡：**「处置会中止运行并等待 provider 静默。所有权与竞态处理见生命周期记录。」

**过度详细：**在每个 disposer 旁边重复生命周期记录的 promise 编排与被否定的所有权模型。

把行为与完成保证留在调用方需要它们的地方。算法与理由积极链接；链接不能替代本地契约。

## 已完成的实施记录保留验证契约

**过度精简：**因为记录已经交付，把整个「验证」一节删掉。

**平衡：**「单测覆盖发布前后的取消、处置静默与 provider 重载。`npm run verify:host` 覆盖真实装配路径；消息文本解析的覆盖缺口已命名，因为文本格式随 dsh 版本推进。」

**过度详细：**逐文件走查 fixture 与断言，没有额外的行为区分。

删迁移任务与测试叙述。保留层级、它们钉住的行为、真实入口路径与有名有姓的覆盖缺口。

## 安全边界可能需要一个具体例子

**过度精简：**「挂载的插件共享宿主的权限。」

**平衡：**「挂载的插件共享宿主的权限；例如 `runShell` 以 `danger-full-access` 执行，等于拿到宿主执行器权限下的任意命令。」

**过度详细：**列出插件可能滥用的每个服务与每个假设的攻击路径。

当抽象的安全限制靠一个例子才能操作化时，保留一个例子。

## 完全删除推理转录

**过度详细：**「循环先检查值是否缺失。缺失时下一个分支提前返回。否则继续，这就是最后那个断言安全的原因。」

**平衡：**代码已经表达了这些分支时不写注释。提前返回保护的是非显而易见的不变量时，只陈述那个不变量。

不要把推理转录压缩成更短的叙述；删掉它。

## 配置注释解释配置树表达不了的东西

**过度详细：**「这一行加载本地文件系统 provider，然后是策略插件，再然后是读、写、编辑工具。」——相邻条目已经展示了这个顺序。

**平衡：**「在面向模型的工具之前加载策略，使其写与编辑调用经过先读后改的闸门。」

保留顺序的后果、意外的范围规则或安全边界。让配置自己展示它的清单。

## 不要只为字数精简

**当前：**「适配器把 provider 错误转换成共享错误类型，使调用方能统一处理认证、限流与瞬态失败。」

**更短但更差：**「适配器规范化 provider 错误。」

**平衡的决定：**保留当前句子，除非链接或周围契约已经列出这些失败类别。更短的版本丢掉了后果与区分，却没有改善结构。

## 用户可见文案遵循所有权

**过度精简：**「工具在调用失败时返回错误。」

**过度详细：**把另一个包的 schema 与渲染字符串抄进本模块的文档。

**平衡：**引用本模块拥有的稳定文案。schema 与另一个包拥有的文案分别链接到其拥有者；本地只陈述本模块自己的条件或差异。

措辞一旦到达模型或用户就是行为，但复制仍然会漂移。精确性属于拥有者。

纯散文审计可以指出可疑措辞，但不能在拥有它的验证场景不存在时悄悄改动。保持不变并报告延后，或把授权范围扩大到包含拥有者场景与所需证据。

## 生成的摘要必须独立成立

**过度精简：**「审批请求与策略服务。」拥有者在后面解释了策略顺序与审计日志，但生成目录只导出第一句。

**过度详细：**把服务的完整生命周期与提示行为搬进被抽取的那句话。

**平衡：**「审批服务：在应答者之前应用会话策略，并把每次询问/结果对记录到发起会话。」非目录细节留在后面的句子里。

知道生成器抽取什么。那个片段必须保存其生成输出上所需的契约。

## 限制是契约，不是债务清单

**过度精简：**省略「配置变更有进程级缓存、需要重载插件」这一事实。

**过度详细：**列出没有调用方或维护后果的私有清理函数与仅测试用的访问器。

**平衡：**「provider 选择在插件生命周期内缓存；安装或修复 provider 需要重载。」普通清理留在它自己的 `TODO` 或计划记录里。

保留影响使用或安全维护的缺口与非显而易见约束。README 不是 backlog 垃圾场。
